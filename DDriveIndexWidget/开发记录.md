# 开发记录 — D-DriveIndexWallpaper

> 从单文件原型到模块化桌面悬浮面板的演进记录。语言/框架：C# 5 + .NET Framework 4.x WinForms，csc 直接命令行编译，无工程文件。

## v1 — 壁纸层嵌入尝试（已废弃）

- 目标：把索引画在"动态壁纸层"（WorkerW/Progman 之间）。
- 做法：发送消息让 Progman 生成 WorkerW，再把窗口 `SetParent` 进去。
- 结果：**本机 DWM 不会合成该层的子窗口**，肉眼无任何变化。
- 教训：壁纸层方案与系统 DWM 版本强相关，放弃嵌入、改为独立顶层悬浮窗。

## v2 — 全屏透明宿主 + 沉底 + 点击穿透

- 顶层 Form 覆盖整块屏幕，背景设为品红 `TransparencyKey`，品红像素被 DWM 抠空 → 全透明。
- `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`：不进任务栏、不抢焦点；`ShowWithoutActivation`。
- 1 秒定时器反复 `SetWindowPos(HWND_BOTTOM)` 沉底，使其位于普通窗口之下。
- `WM_NCHITTEST`：面板矩形外返回 `HTTRANSPARENT`，实现面板外鼠标完全穿透（可点桌面图标）。
- 教训：对色键窗口截图（PrintWindow）会得到黑色，视觉效果只能由人眼验收。

## v3 — 树索引与实时更新

- TreeView 全量懒加载（文件夹+文件、任意深度）；单击标签 `Process.Start(UseShellExecute=true)` 系统默认打开。
- 噪音目录过滤（系统目录、隐藏/系统属性、ReparsePoint、desktop.ini 等）。
- 自定义 `IndexTreeView`：吞掉 `WM_LBUTTONDBLCLK`（双击永不折叠）；`TVM_HITTEST` 区分 +/- 小按钮、图标、标签与空白。
- 自绘行：TreeView 的节点 `BackColor` 在视觉样式开启时不生效，必须 `OwnerDrawText` 才能画出蓝色选中/高亮；白字 + 1px 黑描边保证在任何壁纸上可读。
- `FileSystemWatcher`（递归、64K 缓冲）→ 700ms 防抖 → 只重建已展开分支；重建前后做路径集合**对称差**，新增/删除的行蓝色填充并 `EnsureVisible` 定位，15 秒消退。
- 折叠态小条最初被任务栏遮住：定位一律改用 `Screen.PrimaryScreen.WorkingArea`，不用 `Bounds`。
- 开机自启：`-install` 经 WScript.Shell COM 写启动目录快捷方式（WindowStyle=7 最小化），单实例 Mutex。

## v4 — 无边框悬浮面板形态（当前形态）

- 去掉一切边框/标题与多余背景，只留树本身浮在桌面上；右上角悬浮 `Add` / `☰` 胶囊按钮。
- **按下与拖动的判定（关键设计）**：树控件会吃掉鼠标消息，直接在节点上拖不动面板。
  解决：`IndexTreeView` 拦截 `WM_LBUTTONDOWN` 一律吞掉并 `SetCapture`；宿主记录起点，移动超过阈值（距离² ≥ 36）才进入 Move 拖动，否则在 `WM_LBUTTONUP` 时按命中结果执行"展开/打开"。这样面板任意位置都能拖，且单击、展开互不误伤。
- 缩放热区：四边 8px + 三角 14px 的 Panel。品红背景的热区虽然存在但**其像素被抠空导致鼠标穿透**，因此平时让热区保持品红（隐形、不拦截），50ms 轮询鼠标位置，靠近面板边缘时才把该热区改成实色并 `BringToFront()`，离开恢复品红。
- 右下角常驻 ◢ 握柄按钮（窗体级子控件，永远在树之上），保证最基本的缩放始终可用。
- 尺寸：默认屏宽 1/5 × 工作区高 2/3，右下停靠；`Clamp` 限制 200×140 起、宽 ≤ 3/4 屏、高 ≤ 整屏；矩形持久化到 settings。
- 文件夹筛选：`H|` 隐藏、`A|` 深层挂接；二级目录显隐只需 Hidden，深层目录进 Added 当"固定项"。
- **DPI 踩坑**：外部枚举窗口得到 1500×1000、4px 边条，一度误判几何错误；在程序内打日志自检才发现本机物理屏 3000×2000 @200%，外部工具被系统 DPI 虚拟化，程序内几何（600×1269、16px 边条）本来就正确。→ 结论：DPI 问题以**进程内日志**为准。

## v5 — 模块化拆分 + 配色调整（本次）

- 将 1400+ 行单文件按职责拆成 14 个 `.cs`，目录按功能划分（Native / Infrastructure / Indexing / Controls / Dialogs / UI）；`MainForm` 用 5 个 partial 文件承载。功能与 v4 完全一致，csc 多文件一次编译通过。
- 配色集中到 `Infrastructure/WidgetColors.cs`：
  - 悬停缩放条：深灰 `(45,52,60)` → **浅蓝 `(130,180,245)`**；
  - 右下角常驻握柄：深灰胶囊 → **深蓝 `(18,62,128)`**；
  - 实时高亮蓝 `(41,115,200)`、选中灰蓝等其余颜色不变。
- 经验：改色只动配色常量一处，不在多个绘制点硬编码（参考此前"灰条来源未定位就多点改动导致回退"的教训），改后由人眼在桌面确认。

## v6 — 去盘符行、纯净握柄、Ctrl+滚轮字号（本次）

- **去掉 "D:" 合成根节点**：原先树第一行是合成的 `D:` 根，它处于选中态时由自绘逻辑画了一整条铺满面板宽度的深色选中底（截图中的"顶部黑 bar"）。改造后树的根级直接是二级文件夹 + 挂接项，`LoadChildren` 不再有 D:\ 特判，实时刷新的路径收集/查找改为在 `TreeNodeCollection` 上递归；右键菜单的"根节点特判"同步删除。顺带移除了所有选中态底色（单击即打开，选中态无意义），现在树区只有实时更新时才出现蓝色行。
- **右下角握柄纯净深蓝**：`ConfigurePill` 样式带来了按钮描边/悬停变色；改为显式设置 FlatStyle 无边框、`BorderColor`/`MouseOverBackColor`/`MouseDownBackColor`/`UseVisualStyleBackColor=false` 全部锁成同一深蓝 `(18,62,128)`、无文字，20×20 纯色方块。
- **Ctrl+滚轮缩放字号**：窗口有 `WS_EX_NOACTIVATE`，键盘焦点永远不在本进程，普通 `WM_MOUSEWHEEL` 收不到（消息发给焦点窗口）。方案：UI 线程装 `WH_MOUSE_LL` 低级鼠标钩子（`Controls/CtrlWheelHook.cs`），回调里判 Ctrl 按下 + 光标在面板屏坐标矩形内，读取 `MSLLHOOKSTRUCT.MouseData` 高位得滚轮格数，放大/缩小 0.75pt（7–28pt 限位），命中后返回非零**吞掉消息**避免后面的窗口也滚动。字号生效方式：重建树字体 + 一个共享的粗体 `_folderFont`（所有文件夹节点共用一个 Font 实例，缩放时统一替换并 Dispose 旧实例），`ItemHeight = 字号高度+8` 随行高变化；字号以 `F|` 行持久化。
- 教训：①"黑条"类视觉问题先定位到具体绘制点（这次是自绘选中底，不是边框/阴影）；②不抢焦点窗口要响应滚轮/键盘类输入，低级钩子或 Raw Input 是正路，不要指望控件的 MouseWheel 事件。

## v7 — 彻底去掉不透明元素（重启后复现）（本次）

- 现象（重启后截图）：面板右侧出现整条**不透明白色竖轨**，顶部 Add/☰ 在浅壁纸上近似两个**黑色方块**。根因：①白色竖轨是 TreeView 自带的系统滚动条轨道——重启后恢复了较窄的保存尺寸，内容溢出即出现；②两个按钮本来就用深色实底 `(45,52,60)`。
- **滚动条**：`IndexTreeView.CreateParams` 加 `TVS_NOSCROLL (0x2000)`，横/纵滚动条永不显示（树宽全透明到边缘；长名称 EndEllipsis + `ShowNodeToolTips` 悬停显示全名）。滚动改由低级钩子转发：`CtrlWheelHook` 升级为 `MouseWheelHook`，悬停面板时普通滚轮 → `WM_VSCROLL`/`SB_LINEUP/DOWN`（行数读 `SPI_GETWHEELSCROLLLINES`，为 0 时翻页），Ctrl+滚轮 → 字号；两种情况都吞掉消息，背后窗口不联动。
- **文字按钮**：新增 `Controls/GlyphButton.cs`——背景填充色键色（全透），自绘黑描边白字，悬停变浅蓝；AutoSize 让可点的非色键像素集中在字形上（色键窗口只有非品红像素能接收鼠标）。Add/☰ 不再有任何实底，仅保留用户明确要求的右下角深蓝方块。
- 教训：③色键透明方案下，一切"系统自绘 chrome"（TreeView 滚动条轨道、按钮主题底）都会露出不透明区域——要纯透明就必须把这些 chrome 全部关掉并自己实现交互。

## v9 — 根级文件夹 +/− 按钮消失修复（本次）

- 现象：面板上每个文件夹前的 `+` 不见了，目录无法展开。
- 根因（v6 引入的回归）：v6 去掉合成 `D:` 根节点后，二级文件夹全部变成 TreeView 的**根级节点**。树配置是 `ShowLines=false`，WinForms 在此情况下**永不输出 `TVS_LINESATROOT`**；而 Win32 规则是根级节点必须同时具备 `TVS_HASBUTTONS | TVS_LINESATROOT` 才绘制展开按钮，且 `TVM_HITTEST` 也不会对其返回 `TVHT_ONITEMBUTTON`——于是按钮不显示、点击展开也失效。子级节点仅靠 `TVS_HASBUTTONS` 有按钮，所以 v6 前（二级文件夹还是 `D:` 的子节点）一直正常。
- 排查方式：挂件是色键透明窗口，截图全黑无法直接验收；另写了一个普通白底窗口的最小复现程序（左右两棵树，配置与挂件一致，右树在 `CreateParams` 强制按钮样式），`PrintWindow` 截图对比：左树根级无按钮、右树根级 `−/+` 齐全。同时验证了是否在 manifest 声明 comctl32 v6 依赖渲染结果一致（`EnableVisualStyles()` 已生效），故**不改 manifest**。
- 修复：`IndexTreeView.CreateParams` 在 `TVS_NOSCROLL` 之外强制 `TVS_HASBUTTONS (0x0001) | TVS_LINESATROOT (0x0004)`，保持不加 `TVS_HASLINES`——按钮回来、依然没有连线。
- 教训：⑤"去掉合成根节点"这类结构调整会改变节点在原生控件中的层级语义，根级与子级的样式/命中规则不同；TreeView 样式位以 Win32 文档为准，必要时绕过 WinForms 属性封装直接在 `CreateParams` 置位。⑥透明挂件的视觉问题可用"同配置普通窗口 + PrintWindow"间接复现取证。

## v10 — 右键菜单导致顶部文件夹蓝条修复（本次）

- 现象：右键面板上**任意**文件夹，蓝色选中条总是出现在最顶部的根级文件夹而非右键对象；但菜单（Open / Hide from panel）作用的节点是正确的。
- 根因：窗口带 `WS_EX_NOACTIVATE`，树从不持有焦点。右键弹出 `ContextMenuStrip` 时，菜单引发的焦点变化使原生 TreeView 在"当前无 caret"时**自动选中第一可见节点**（`TVGN_CARET` 的默认行为）；`OwnerDrawText` 模式下该选中由系统画成蓝条。代码从未设置过 `SelectedNode`，`MouseDown` 里 `GetNodeAt` 得到的右键节点也正确，所以菜单动作对、仅蓝条永远跳顶。
- 修复：订阅 `TreeView.AfterSelect`，凡是原生控件自行产生的选中（`e.Node != null`），用 `BeginInvoke` 异步把 `SelectedNode` 清空（不能在 `TVN_SELCHANGED` 通知内同步重入），回调前判 `IsDisposed/IsHandleCreated`。单击本就即时打开、挂件也没有键盘选择，清空 caret 无任何副作用，蓝条在重绘前即被撤销、无闪烁。
- 教训：⑦不持有焦点的无激活宿主里，弹菜单/对话框引起的焦点抖动会触发控件"无选中项时的默认选中"；不能因为代码从不赋值 `SelectedNode` 就认为选中态不存在，必须在选择变更事件里显式丢弃。

## v11 — 文件名截断规则修正：短名不再误显示省略号（本次）

- 现象：仅两个汉字的"简历"文件夹被显示成"简..."。用户要求的规则是：完整显示至多 12 个汉字（或等宽的 24 个英文字符），只有超过 12 汉字宽度的名字才截成"前 12 汉字 + ..."。
- 根因：截断完全发生在绘制层——`TreeDrawNode` 使用 `TextFormatFlags.EndEllipsis` 让 GDI 按像素省略，而文字布局矩形直接用了 `DrawTreeNodeEventArgs.Bounds`。该原生 label 矩形在 `TVS_NOSCROLL` 配置下可能异常窄，于是任何短名字都可能被像素级省略；代码中本不存在按字符数截断的逻辑。
- 修复（`UI/MainForm.Tree.cs`）：
  - 新增 `TruncateLabel`：按显示宽度计量（CJK/全角字符计 2，其余计 1，预算 24 单位），预算内完整返回；超出则取前缀 + "..."；代理对（emoji 等）整体计数，不会截出半个字符。`IsWideGlyph` 覆盖 CJK 统一汉字/扩展 A、假名、谚文、全角标点等常见宽字符区间。
  - `MakeNode` 的节点 `Text` 改用截断后文本，`ToolTipText` 仍保留全名，悬停可看全称；打开操作走 `NodeItem.Path`，不受影响。
  - 绘制矩形从 `e.Bounds` 改为延伸到树客户区右缘的 `bar`，并去掉 `EndEllipsis`（改加 `NoPrefix`，避免文件名中的 `&` 被当助记符），从根上消除短名误省略。
- 教训：⑧OwnerDraw 的 TreeView 不要盲信 `e.Bounds` 给的宽度，文字布局矩形应自行按客户区右缘计算；"省略号"类需求先明确是按字符规则还是按像素规则，不要把字符预算交给 GDI 的矩形宽度隐式决定。

## 关键技术清单（备忘）

1. 透明：`Form.BackColor = TransparencyKey = Magenta`，所有要抠空的控件同色；实色控件（按钮/高亮条）正常可见。
2. 不抢焦点：`WS_EX_NOACTIVATE` + `ShowWithoutActivation`；菜单/对话框是例外（本就需要交互）。
3. 点击穿透：宿主全屏，`WM_NCHITTEST` 面板外 → `HTTRANSPARENT`。
4. 沉底：1 秒 `HWND_BOTTOM`；最小化时先 `SW_RESTORE`。
5. 单击与拖动共存：吞按下 + SetCapture + 移动阈值 + 松开标定。
6. TreeView 自绘才能改行底色；文件夹加粗靠 `NodeFont`。
7. 实时刷新：防抖 + 仅重建展开分支 + 路径集合对称差高亮。
8. 高分屏：PerMonitorV2 manifest；坐标/DPI 以进程内实测为准。
